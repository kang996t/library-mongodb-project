# 任务四 GridFS 文件清单与下载校验记录

核对日期：2026-11-11

本记录只保存检查时从项目 MongoDB 只读查询得到的文件元数据，以及仓库已有的本地文件大小；没有执行上传、删除或覆盖操作。

## 一、文件清单实现核对

项目中没有 `list_all_files()` 方法。实际方法名是 `GridFSManager.list_files()`。

该方法从 `fs.files` 查询 `filename`、`length`、`uploadDate` 和 `metadata`，按 `uploadDate` 升序排列，并将 `uploadDate` 映射为返回值中的 `upload_date`。

数据库中的 BSON Date 以 UTC 瞬时值保存。下表保留了带时区的原始读取值；不要用不带偏移的本地格式替换它们。

| 文件 | ISBN | 类型 | `length` | 原始 `uploadDate` |
|---|---|---|---:|---|
| `ebook_1.pdf` | `9787115428028` | `ebook` | 39837 | `2026-11-04T02:56:33.856000+00:00`（UTC） |
| `ebook_2.pdf` | `9787121362726` | `ebook` | 38524 | `2026-11-04T02:56:33.868000+00:00`（UTC） |
| `ebook_3.pdf` | `9787115546081` | `ebook` | 37004 | `2026-11-04T02:56:33.872000+00:00`（UTC） |
| `cover_1.png` | `9787115428028` | `cover` | 23611 | `2026-11-04T02:56:33.877000+00:00`（UTC） |
| `cover_2.png` | `9787121362726` | `cover` | 26053 | `2026-11-04T02:56:33.882000+00:00`（UTC） |
| `cover_3.png` | `9787115546081` | `cover` | 15171 | `2026-11-04T02:56:33.886000+00:00`（UTC） |

注意：项目统一连接模块没有设置 `tz_aware=True`，命令行展示又只格式化到秒，因此当前应用界面会丢失时区偏移。报告应以本记录中的 UTC 原始值为准。

## 二、下载校验实现

项目中没有名为 `verify_file_consistency()` 的方法，实际对应实现是 `GridFSManager.download_and_verify()`。它只接受电子书，读取原始文件大小、GridFS `length` 和下载文件大小，并判断：

```text
original_size == gridfs_size == downloaded_size
```

`ebook_2.pdf`、`ebook_3.pdf` 的原始文件大小与 GridFS `length` 已核对一致，但仓库没有对应下载文件，因此不能声称完成三方下载校验。三个封面文件也不进入当前校验方法，因为方法明确限制 `file_type == "ebook"`。

该记录支持总报告在“文件存储”章节中准确说明校验范围，不应把一个电子书样例扩大表述为六个文件均已完成下载校验。
